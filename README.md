# procko.pro — Tyler T. Procko, Ph.D.

Personal portfolio and CV site for [Tyler T. Procko](https://procko.pro) — AI/Knowledge Graph Engineer, Ontologist, DoD-cleared.

## Architecture

Personal content lives in **`public/data/tyler-procko.yaml`**. The shared term catalog, **`src/data/competencies.json`**, defines competency identities, labels, categories, and aliases.

```
public/data/tyler-procko.yaml   ← single source of truth for all CV/portfolio content
│
├── .github/
│   ├── workflows/
│   │   ├── deploy.yml                        ← build + deploy to GitHub Pages on push to main
│   │   ├── sync-repo-descriptions.yml        ← daily sync of GitHub project descriptions
│   │   ├── discover-new-repos.yml            ← daily discovery; avoids duplicate open PRs and cleans closed branches
│   │   ├── sync-openalex-publications.yml    ← weekly sync of new publications from OpenAlex
│   │   └── check-links.yml                   ← weekly link check
│   └── scripts/
│       ├── sync_openalex_publications.py     ← queries OpenAlex by ORCID; deduplicates, updates citation counts, adds stubs
│       ├── discover_new_repos.py             ← finds public repos and infers technologies/domains from metadata
│       └── sync_repo_descriptions.py         ← syncs project descriptions from GitHub
│
├── build.py                    ← Python/Jinja2 builder → public/legacy/cv.html
│   templates/                  ← Jinja2 partials (one per section)
│
├── public/
│   ├── legacy/cv.html          ← legacy HTML CV (generated by build.py, served at /legacy)
│   ├── data/tyler-procko.yaml  ← personal content fetched by the React app at runtime
│   ├── CNAME                   ← custom domain (procko.pro)
│   └── 404.html                ← SPA routing redirect for GitHub Pages
│
└── src/
    ├── data/competencies.json  ← shared catalog bundled by Vite and read by Python
    ├── lib/
    │   ├── yaml-loader.ts      ← fetches + validates YAML at runtime (Zod)
    │   ├── schema.ts           ← Zod schema matching the YAML structure
    │   ├── cv-data.ts          ← transforms Person → renderer-agnostic CVData/ResumeData models
    │   ├── graph-builder.ts    ← builds Cytoscape node/edge graph from Person data
    │   ├── competencies.ts     ← resolves identities and aggregates supporting records
    │   ├── tech-categories.ts  ← category menu data derived from the shared catalog
    │   └── ui-constants.ts     ← shared Tailwind class tokens for consistent sizing
    ├── components/
    │   ├── SiteFooter.tsx
    │   └── SEO.tsx
    └── pages/
        ├── Landing.tsx         ← boot-sequence animation, skills matrix, publications, projects

        ├── CVExport.tsx        ← full CV as downloadable PDF + HTML preview (/cv)
        ├── ResumeExport.tsx    ← condensed resume as downloadable PDF + HTML preview (/resume)
```

## Updating content

For personal content, edit `public/data/tyler-procko.yaml`. The React app fetches it at runtime — no rebuild needed for content changes. The legacy HTML view requires `python3 build.py` to regenerate.

New publications are synced automatically every Monday via the OpenAlex workflow. Stubs are tagged `source: openalex` and `featured: false` for manual review.

## Maintaining competencies

Add a new term once in `src/data/competencies.json`, then reference it from a portfolio record. Each term has a permanent lowercase `id` (letters/numbers separated by single hyphens), a display `label`, a `category` from the same catalog, and an `aliases` list. IDs, labels, and aliases are accepted in record fields; matching ignores case and surrounding whitespace. Keep the ID unchanged when renaming a label, and add the previous label as an alias if records still use it. Catalog changes require a rebuild.

Homepage chips, project tags, the graph, and React CV/resume skills resolve through `src/lib/competencies.ts`. Category comes from the catalog, not the YAML field. Graph links use stable IDs (`/graph?term=sparql`); free-text `?q=` links also resolve catalog references. Aliases never create additional nodes or counts. Graph links and connected-node navigation reuse the node-click handler, so the selected details, neighbor expansion, and neighborhood dimming stay consistent.

Counts mean distinct supporting records across education, work, publications, projects, courses, certificates, talks, and extracurriculars. A repeated competency within a record counts once. All views use the graph's existing evidence policy: omit `graph_exclude` work/projects and deprecated certificates. Presentation filters remain intentional: ranked chips hide office/communication tools; CV/resume hides OS/personal/domains and shows at most 20 skills per category. The legacy HTML's manually curated skills list is separate from these evidence counts. For projects, `graph_exclude` controls site/graph visibility, while `cv_exclude` independently excludes the project from both CV and resume. Personal & Creative Work stays visible on the site with 19 tools under Personal & Creative Use, but remains excluded from document exports. Telegram is a Communication Tool attached only to the Christian Denominations Wikidata project; the five other previously excluded projects remain hidden with explicit `graph_exclude` flags.

Validation rejects unknown references, duplicate references within a field, duplicate IDs, invalid categories, and ambiguous names/aliases. Field/category disagreements are reported for review; the catalog still determines rendering. Tests compare all real-data competency counts with their graph evidence links. See [classification review](docs/competency-review.md) for unresolved editorial decisions.

```bash
python3 .github/scripts/validate_yaml_terms.py
python3 -m pytest tests/test_skill_validation.py tests/test_discover_new_repos.py tests/test_enrich_projects.py -q
npm test
npm run build
```

Project and recent-repository cards share `CARD_DESCRIPTION` in `src/lib/ui-constants.ts`: descriptions stay within two lines without flex growth; tag rows handle bottom alignment.

## Artwork

`public/art/` is the single source for all 54 drawings. Both `/personal` and `/legacy/personal/personal.html` reference these PNGs directly; the modern gallery also uses them in its lightbox. Keep originals at full quality and avoid duplicating them under `legacy/`. ## Deployment

Pushes to `main` trigger `.github/workflows/deploy.yml`, which:
1. Runs `build.py` to regenerate the legacy HTML from YAML
2. Runs `npm run build` to produce the Vite `dist/`
3. Deploys `dist/` to GitHub Pages at `procko.pro`

The daily repository-description sync uses `AUTOMATION_TOKEN` to open an auto-merge PR after validating updated references. Required PR checks run before merging; the merge to `main` triggers deployment. Unchanged descriptions create no commit or PR. If descriptions change but the token is missing, the job fails explicitly instead of publishing an update that cannot trigger validation. The token needs Contents and Pull requests write permissions, as used by the publication-sync workflow. Sync runs are serialized and only publish from `main`.

Workflow regression checks:

```bash
python3 -m pytest tests/test_description_sync_workflow.py -q
```
